# Czym jest Django?

- Framework webowy w Pythonie (od 2005), zasada *batteries included*
- W pudełku: ORM i migracje, routing URL-i, szablony, formularze, panel admina, logowanie i uprawnienia, tłumaczenia, ochrona przed CSRF / XSS / SQL injection, narzędzia do testów
- **Framework, nie biblioteka**: to Django wywołuje nasz kod – my wypełniamy wyznaczone miejsca (widoki, modele, szablony)
- **Konwencje**: pliki o ustalonych nazwach (`models.py`, `views.py`, `urls.py`, `admin.py`) – w każdym projekcie Django wiesz, gdzie szukać
- Dokumentacja: [docs.djangoproject.com](https://docs.djangoproject.com/en/5.2/) – bardzo dobra, warto ją czytać

# Krok 3: modele

<!-- _class: small -->

```python
# tasks/models.py
from django.conf import settings
from django.db import models


class Task(models.Model):
    short_name = models.CharField(max_length=10, unique=True)
    title = models.CharField(max_length=200)
    statement = models.TextField(blank=True)
    deadline = models.DateTimeField(null=True, blank=True)

    def __str__(self):
        return f"{self.short_name}: {self.title}"
```

- Klasa → tabela `tasks_task`, atrybut → kolumna; kolumnę `id` Django dodaje sam
- `null=True` – dopuszcza `NULL` w bazie; `blank=True` – pole może być puste w formularzu
- `__str__` – jak obiekt wygląda w shellu i w adminie

# QuerySet – zapytania

| Python | SQL (w przybliżeniu) |
| --- | --- |
| `Submission.objects.filter(score=100)` | `WHERE score = 100` |
| `.filter(score__gte=50)` | `WHERE score >= 50` |
| `.filter(task__short_name="sum")` | `JOIN tasks_task … WHERE short_name = 'sum'` |
| `.filter(score__isnull=True)` | `WHERE score IS NULL` |
| `.exclude(score=0)` | `WHERE NOT (score = 0)` |
| `.order_by("-date")[:10]` | `ORDER BY date DESC LIMIT 10` |
| `.count()` / `.exists()` | `SELECT COUNT(*)` / `… LIMIT 1` |

---

# QuerySet – leniwość

```python
qs = Submission.objects.filter(task__short_name="sum")   # brak zapytania
qs = qs.exclude(score=None).order_by("-score")           # nadal brak
best = qs.first()                                        # teraz: 1 zapytanie
for sub in qs:                                           # i teraz: kolejne
    print(sub.user, sub.score)
```

- QuerySet jest **leniwy**: SQL wykonuje się dopiero przy iteracji, `list()`, `len()`, w szablonie
- Filtry można łączyć łańcuchowo; `print(qs.query)` pokazuje SQL
- `get()` – dokładnie jeden wynik, inaczej `DoesNotExist` / `MultipleObjectsReturned`; `first()` – obiekt albo `None`

---

# Relacje – `ForeignKey`

```python
task = models.ForeignKey(Task, on_delete=models.CASCADE, related_name="submissions")
```

- `ForeignKey` = wiele do jednego: wiele zgłoszeń → jedno zadanie (w bazie kolumna `task_id`)
- W obie strony:
  - `sub.task` – obiekt zadania (dodatkowe zapytanie), `sub.task_id` – samo id (bez zapytania)
  - `task.submissions.all()` – zgłoszenia do zadania (bez `related_name`: `task.submission_set`)
- Filtrowanie po relacji: `Submission.objects.filter(task__title__icontains="suma")`

---

# Relacje – usuwanie i inne typy

- `on_delete`: `CASCADE` – usuń razem, `PROTECT` – zablokuj usunięcie, `SET_NULL` – wyzeruj
- Inne relacje: `OneToOneField` (1:1), `ManyToManyField` (n:m, tabela pośrednia)
- W OIOIOI: `Round.contest`, `ProblemInstance.round`, `Submission.problem_instance`

# Język szablonów – zasady

- `{{ zmienna }}` – wartość, **automatycznie escapowana** (ochrona przed XSS); `{% tag %}` – logika; `{{ x|filtr }}`
- `task.title` działa dla atrybutów, kluczy słownika i metod bez argumentów
- Szablon w `templates/tasks/`, nie w `templates/` – szablony wszystkich aplikacji trafiają do jednej przestrzeni nazw
- `{% extends %}` + `{% block %}` – wspólny układ strony w `base.html`, podstrony nadpisują bloki
- Logika należy do widoku – szablon tylko wyświetla przygotowane dane

```python
# tasks/views.py
@login_required
def submit(request, task_id):
    task = get_object_or_404(Task, pk=task_id)
    if request.method == "POST":
        form = SubmissionForm(request.POST)
        if form.is_valid():
            sub = form.save(commit=False)
            sub.task = task
            sub.user = request.user
            sub.save()
            return redirect("task_detail",
                            task_id=task.id)
    else:
        form = SubmissionForm()
    return render(request, "tasks/submit.html",
                  {"form": form, "task": task})
```

```python
# tasks/urls.py

     name="submit"),
```

- `is_valid()` – walidacja pól i `clean_<pole>()`, błędy trafiają do `form.errors`
- `save(commit=False)` – obiekt bez zapisu, uzupełniamy `task` i `user`
- `redirect(...)` – po sukcesie przekierowanie (następny slajd)

# Użytkownicy i logowanie

- `django.contrib.auth`: model `User` (`username`, `is_staff`, `is_superuser`), grupy, uprawnienia
- `request.user` – zawsze ustawiony: `User` albo `AnonymousUser`
  - sprawdzenie: `request.user.is_authenticated`, w szablonie `{% if user.is_authenticated %}`
- `@login_required` – niezalogowany → przekierowanie na stronę logowania
- Gotowe widoki logowania / wylogowania: `django.contrib.auth.views`
- Hasła: tylko hasze (`user.set_password(...)`), nigdy otwarty tekst
- OIOIOI dokłada własne warunki (`enforce_condition`) i uprawnienia per konkurs – za chwilę

# Typowe pułapki na początku

<!-- _class: small -->

- Aplikacja nie dodana do `INSTALLED_APPS` → modele i szablony „nie istnieją”
- Zmieniony model bez `makemigrations` / `migrate` → `no such column` / `ProgrammingError`
- Szablon w `templates/` zamiast `templates/<app>/` → kolizje nazw między aplikacjami
- Brak `{% csrf_token %}` w formularzu → `403 Forbidden` przy POST
- `datetime.now()` zamiast `timezone.now()` (w OIOIOI: `request.timestamp`) → kłopoty ze strefami czasowymi
- `Task.objects.get(...)` w widoku bez obsługi `DoesNotExist` → błąd 500; lepiej `get_object_or_404`
- `{{ task.submissions.count }}` w pętli → osobne zapytanie dla każdego zadania (problem **N+1**)
- Ręczne zmiany w bazie zamiast migracji → u innych baza wygląda inaczej

# Modele w OIOIOI

Fragment `oioioi/contests/models.py`:

```python
class Round(models.Model):
    contest = models.ForeignKey(Contest, verbose_name=_("contest"),
                                on_delete=models.CASCADE)
    name = models.CharField(max_length=255, verbose_name=_("name"))
    start_date = models.DateTimeField(default=timezone.now)
    end_date = models.DateTimeField(blank=True, null=True)
    is_trial = models.BooleanField(default=False)

    class Meta:
        unique_together = ("contest", "name")
        ordering = ("contest", "start_date")

    def clean(self):
        if self.start_date and self.end_date and self.start_date > self.end_date:
            raise ValidationError(_("Start date should be before end date."))
```

# URL-e w OIOIOI

# oioioi/contests/urls.py (fragment)
c_patterns = [
    path("", views.default_contest_view, name="default_contest_view"),

def problem_statement_view(request, problem_instance):
    controller = request.contest.controller
    pi = get_object_or_404(ProblemInstance, round__contest=request.contest,
                           short_name=problem_instance)
    if not controller.can_see_problem(request, pi):
        raise PermissionDenied                      # → 403
    ...
    return TemplateResponse(request, "contests/problem_statement.html",
                            {"problem_instance": pi, ...})

# Formularze w OIOIOI

```python
class SubmitMessageForm(forms.ModelForm): ...       # formularz z modelu

def edit_view(request):
    if request.method == "POST":
        form = MyForm(request.POST, request.FILES)
        if form.is_valid():                        # walidacja pól + clean()
            do_something(form.cleaned_data)
            return redirect("my_submissions")      # POST → redirect → GET
    else:
        form = MyForm(initial={...})
    return TemplateResponse(request, "template.html", {"form": form})
```
