# Jak OIOIOI ładuje aplikacje

`oioioi/urls.py` (fragment):

```python
for app in settings.INSTALLED_APPS:
    if app.startswith("oioioi."):
        # Django imports views lazily, and since there are some decorators
        # that have to run, all views need to be imported at startup.
        try_to_import_module(app + ".views")
        # Controllers should be imported at startup, because they register
        # mixins.
        try_to_import_module(app + ".controllers")
        urls_module = try_to_import_module(app + ".urls")
        if hasattr(urls_module, "urlpatterns"):
            urlpatterns += urls_module.urlpatterns
```

Import modułu = efekty uboczne: rejestracja w menu, `mix_in(...)`, URL-e.

# Kontrolery

Logika i reguły konkursu **nie** siedzą w widokach, tylko w kontrolerze.

```python
class Contest(models.Model):
    controller_name = DottedNameField(
        "oioioi.contests.controllers.ContestController", verbose_name=_("type"))

    @property
    def controller(self):
        return import_string(self.controller_name)(self)
```

- W bazie zapisana jest **nazwa klasy**, np. `oioioi.oi.controllers.OIContestController`

# Przykład metody

<!-- _class: small -->

```python
def can_see_round(self, request_or_context, round, no_admin=False):
    """Determines if the current user is allowed to see the given round.

    If not, everything connected with this round will be hidden.

    The default implementation checks if the round is not in the future.
    """
    context = self.make_context(request_or_context)
    if not no_admin and context.is_admin:
        return True
    rtimes = self.get_round_times(request_or_context, round)
    return not rtimes.is_future(context.timestamp)
```

- `request_or_context` – można przekazać `request` albo `ContestControllerContext` (contest, timestamp, is_admin)
- `request.timestamp` zamiast `timezone.now()` – pozwala „cofać czas” (aplikacja `clock`, admin)

# Konkurs a zadanie – zasady

- Kontroler konkursu **może** wołać kontroler zadania, odwrotnie – **nie**
- Domyślnie `ContestController.create_submission`, `judge`, … delegują do `ProblemController`
- Poza kodem kontrolerów używaj `problem_instance.controller`, nie `problem_instance.contest.controller`

---

# Mixiny – problem

<!-- _class: small -->

- Aplikacja `rankings` chce, żeby **każdy** konkurs miał `ranking_controller()` i unieważniał ranking po zmianie wyników
- Nie możemy edytować `ContestController` (to inna aplikacja) ani każdej podklasy
- Zwykłe dziedziczenie wymaga podania mixinów w miejscu deklaracji klasy

Rozwiązanie OIOIOI: **`ObjectWithMixins`** + `mix_in()` – dodawanie mixinów „z zewnątrz”, w trakcie importu

![w:1100 Łańcuch super() przez mixiny](diagramy/mixiny-mro.svg)

Uproszczone MRO: mixin ląduje między klasą a jej bazą, więc każdy `super()` przekazuje wywołanie dalej.

---

# Mixiny – przykład z `rankings`

<!-- _class: small -->

```python
# oioioi/rankings/controllers.py
class RankingMixinForContestController:
    """ContestController mixin that sets up rankings app."""

    def ranking_controller(self):
        """Return the actual :class:`RankingController` for the contest."""
        return DefaultRankingController(self.contest)

    def update_user_results(self, user, problem_instance, *args, **kwargs):
        super().update_user_results(user, problem_instance, *args, **kwargs)
        self.ranking_controller().invalidate_pi(problem_instance)


ContestController.mix_in(RankingMixinForContestController)
```

- Mixin dotyczy też wszystkich podklas (`OIContestController`, `ACMContestController`, …)
- **Zawsze** wołamy `super()` – inaczej przerywamy łańcuch innych mixinów

---

# Mixiny – na co uważać

- Mixin trzeba dodać **przed** utworzeniem pierwszej instancji klasy (inaczej `assert`)
- Kolejność mixinów = kolejność `INSTALLED_APPS` → kolejność w MRO
- Nie tylko kontrolery: także `ContestAdmin`, `ProblemInstanceAdmin`, `SubmissionAdmin`

```python
ContestAdmin.mix_in(ComplaintsAdminMixin)            # complaints/admin.py
ProgrammingContestController.mix_in(
    SimilarityDisqualificationMixin)                 # similarsubmits/
ContestController.mix_in(TeamsMixinForContestController)   # teams/
```

Szukanie: `git grep "mix_in(" oioioi/`

# Uprawnienia – warunki

<!-- _class: small -->

`oioioi/base/permissions.py`: **`Condition`** – funkcja zwracająca `bool`, z operatorami `&`, `|`, `~`

```python
@make_request_condition
@request_cached
def can_enter_contest(request):
    rcontroller = request.contest.controller.registration_controller()
    return rcontroller.can_enter_contest(request)


@enforce_condition(contest_exists & is_contest_basicadmin)
def edit_submit_message_view(request):
    ...
```

- `enforce_condition` – brak spełnienia → przekierowanie do logowania albo 403 (lub `template=`)
- Te same warunki można podpiąć pod pozycje menu (`condition=...`)

# Krok 3: formularz pyta kontrolery

# Krok 5: ocenianie

`ProblemController.judge` (`oioioi/problems/controllers.py`):

1. Tworzy **environ** – słownik opisujący zadanie oceniania
2. `fill_evaluation_environ` – kontrolery dopisują *recipe*: listę kroków (kompilacja, testy, …)
3. Dokłada kroki końcowe: `update_submission_score`, `update_user_results`, `call_submission_judged`, …
4. `finalize_evaluation_environment` – ostatni hook dla kontrolera konkursu
5. `delay_environ(environ)` → kolejka **evalmgr** (Celery) → **sioworkers** → sio2jail

Szczegóły tej drogi: osobne zajęcia „Ocenianie zgłoszeń od początku do końca”.

# ast-grep – własna reguła

<!-- _class: small -->

<div class="cols"><div>

```yaml
# rules/mixin-bez-super.yml
id: mixin-bez-super
language: python
severity: warning
message: Metoda mixinu nie woła super()
rule:
  kind: function_definition
  has:
    field: name
    regex: ^(can_submit|update_user_results|adjust_submission_form)$
  inside:
    kind: class_definition
    has: { field: name, regex: Mixin }
    stopBy: end
  not:
    has: { pattern: super(), stopBy: end }
```

</div><div>

# Testy – organizacja

- Testy w `<app>/tests.py` lub `<app>/tests/` (konfiguracja: `pytest.ini`)
